# Google Drive integration — implementation and acceptance plan

Status: active development on `feature/drive-finishing-integration`. No production deployment authorised. Live Drive transfers remain unverified until owner completes Google Cloud setup and performs disposable tests.

## Confirmed baseline
- Studio 0.2.48 base; OAuth uses the narrow `drive.file` scope. Owner screenshot currently shows Google error 400 `redirect_uri_mismatch`; sign-in has not completed.
- Current redirect address is generated by WordPress and shown in Settings. It must exactly match Google's allowed redirect URI, including `www`.
- Google Drive is separate from ChatGPT's Drive connection. No assumption of prior Drive connection applies here.
- Existing AF draft register: 1LQQAciLLM77nQTiUqaQcOvrpFlUyAWFymX3jWIt8Kb8.
- AF-first policy unresolved. No AF allocation or catalogue writes.

## Implemented in this development branch
- Encrypted OAuth token refresh with a shared lock, expiry margin, scope check and reconnect errors.
- Google Picker image selection and destination-folder selection; selected IDs are rechecked by Drive API under the narrow `drive.file` permission.
- Image imports verify MIME, file size, image bytes, dimensions and MD5 before preserving a local original. Re-importing a previously imported Drive file reopens the same workspace.
- Approved package save is a separate action after explicit local human review. It creates a new Drive file, verifies folder, size and MD5, and uses an app property to safely detect a completed retry.
- No AF/SB allocation, Google Sheets writes, catalogue edits, final-production writes, or overwrites are enabled.
- Picker requires Google Picker API enabled and a website-restricted API key. Google requires the site's origin and `https://docs.google.com/*` under website restrictions, and Google Picker API plus Drive API under API restrictions.

## Implementation stages
1. Complete Cloud configuration and correct redirect URI mismatch. Create and restrict a browser API key for Google Picker.
2. Obtain owner sign-in and consent, then test token refresh, revoke, expiry, and reconnect.
3. Test Picker browsing, denied access, inaccessible file, duplicate selection, PNG/JPEG/WebP import, and checksum preservation.
4. Test local processing, workspace reopen, compare, human review, local approval, and package construction.
5. Test destination folder choice, package upload, checksum verification, partial failure, and safe retry with disposable files.
6. Test Android Chrome and magnification. No Android-specific test has yet run.
7. Run PHP syntax, JavaScript, workflow and existing Studio regressions on GitHub Actions. Local shell has no PHP runtime.

## Acceptance tests
- OAuth connected, refresh, revoke, expiry and disconnect (owner action required for live verification).
- Picker access granted/denied, duplicate selection, inaccessible file.
- Import exact original checksum; reject invalid image and oversized file.
- Upload verified parent, content and retry without duplicate or overwrite.
- Local versioning, comparison, cancel, review, download.
- Tablet touch targets, local picker and readable error messages.
- Unauthenticated and invalid-CSRF requests rejected.
- Characters, Freestyle, Catalogue, Usage and Settings regressions.
- Zero changes to AF register, Ideas, SB Catalogue, lifecycle tracker and Final Production.

## Release gate
